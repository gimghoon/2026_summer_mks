# 최근 지시어 기반 추가 설명 설계

## 문제

답장 생성 전 모호성 검사가 선택된 전체 대화에서 `그거`, `걔`, `그 일` 같은 지시어를 하나라도 발견하면 모델 충분성 판단을 건너뛰고 추가 설명을 요구한다. 이 때문에 대화 중간의 이미 해결된 표현도 현재 요청을 영구적으로 막는다. 실제 사례에서는 과거의 `난 그거 아니야^^` 때문에 사용자가 현재 상황과 의도에 `이민서`를 명시한 뒤에도 API가 반복해서 `409 clarification_required`를 반환했다.

## 목표

현재 답장과 가까운 미해결 지시어만 결정적으로 차단한다. 과거 대화에 지시어가 존재하더라도 최근 발화가 명확하면 답장 생성을 계속하며, 사용자가 현재 상황이나 의도에서 실제 참여자 이름을 명시하면 해당 사람 지시어가 해결된 것으로 인정한다.

## 동작

- 지시어 검사는 선택된 전체 맥락이 아니라 마지막 3개 텍스트 발화만 검사한다.
- 마지막 3개 발화에 `그거`, `그것`, `걔`, `그 사람`, `그 일` 등의 현재 지원 표현이 있으면 기존처럼 맥락을 20→40→80→전체 청크로 확장한다.
- 전체 청크까지 확장한 뒤에도 최근 지시어가 남고 해결 근거가 없으면 기존 한국어 질문 하나를 반환한다.
- 현재 상황 또는 답장 의도에 해당 대화방의 실제 참여자 이름이 포함되면 사람을 가리키는 최근 지시어는 해결된 것으로 간주하고 충분성 판단을 진행한다.
- 임의의 일반 명사는 참여자 이름으로 취급하지 않는다. 비교 대상은 현재 방에서 로드한 참여자 이름으로 제한한다.
- `그래서` 같은 기존 오탐 방지와 조사 결합형 `걔는`, `그거야`, `그것을` 탐지는 유지한다.

## 구조

- `context-expander.ts`는 최근 텍스트 발화 범위와 명시적 참여자 해결 여부만 입력받아 결정적 모호성을 판단한다.
- `production-context.ts`는 방 참여자 이름과 사용자의 `situation`·`intent`를 비교해 명시적 참여자 해결 여부를 계산해 전달한다.
- 일반적인 단위 테스트 호출은 기본값 `false`를 사용하므로 기존 API 호환성을 유지한다.

## 오류 처리와 개인정보

- 참여자 이름 비교는 이미 로컬에서 복호화된 현재 방 데이터로만 수행한다.
- 이름이나 대화 원문을 새 로그, 오류 응답, 검증 규칙 ID에 추가하지 않는다.
- 추가 설명이 실제로 필요할 때 반환하는 문구와 `409` 응답 형식은 변경하지 않는다.

## 테스트

- 오래된 `그거` 뒤에 명확한 최근 발화가 있으면 충분성 judge가 호출되고 답장 흐름이 진행되는지 검증한다.
- 마지막 3개 발화의 조사 결합형 지시어는 계속 확장·질문을 유발하는지 검증한다.
- 최근 사람 지시어가 있어도 현재 상황이나 의도에 실제 참여자 이름이 있으면 judge로 진행하는지 검증한다.
- 실제 참여자 이름이 아닌 일반 명사는 해결 근거가 되지 않는지 검증한다.
- 프로덕션 컨텍스트 통합 테스트에서 현재 사례와 같은 오래된 `그거` + 명시된 대상이 `needsUserQuestion: false`가 되는지 검증한다.

## 제외 범위

- 모델 프롬프트, 답장 강도 1~7, 검색 순위, 프로필, 저장 스키마는 변경하지 않는다.
- 대명사 전체에 대한 자연어 상호참조 모델을 새로 만들지 않는다.
- 사용자가 작성한 현재 상황이나 의도를 자동 수정하지 않는다.
