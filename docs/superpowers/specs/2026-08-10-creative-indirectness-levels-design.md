# 창의적 돌려 말하기 6·7단계 설계

## 목표

기존 답장 강도 1~5에 6단계와 7단계를 추가한다. 6단계는 뜻을 충분히 추론할 수 있는 강한 암시, 7단계는 현재 대화의 소재를 활용한 창의적인 우회 표현을 만든다.

## 사용자 경험

- 설정 화면과 답장별 강도 조절 범위를 1~7로 확장한다.
- 6단계는 감정이나 요구를 직접 진술하지 않고 상황 묘사, 반문, 말끝 흐리기, 여운으로 전달한다.
- 7단계는 대화 속 사건이나 표현을 재료로 삼아 상황 빗대기, 장난스러운 암시, 조용한 여운의 세 전략으로 후보를 구분한다.
- 7단계 문장도 실제 카카오톡 답장처럼 짧고 자연스러워야 하며, 맥락과 무관한 시적 표현이나 난해한 비유는 허용하지 않는다.
- 예: “또 늦어서 서운해”를 7단계로 표현하면 “오늘도 시계는 나만 보고 있었나 봐 ㅎㅎ”처럼 핵심 상황을 남기되 감정을 직접 선언하지 않는다.

## 정책과 안전 경계

- 강도 1~5의 현재 의미와 동작은 유지한다.
- 6단계 허용 장치는 `상황 묘사`, `완곡한 반문`, `말줄임`, `함축`, `감정 단서`, `여운`이다.
- 7단계 허용 장치는 6단계 장치에 `맥락 비유`, `장난스러운 역설`, `조용한 여운`을 추가한다.
- 모델은 입력 대화에 실제로 존재하는 소재만 비유나 암시에 사용해야 한다. 새로운 장소, 날짜, 약속, 물건, 관계 사실을 지어내지 않는다.
- 돈, 동의, 안전, 확실한 거절, 중요한 약속에서는 6~7단계에서도 결정 자체를 명확하게 유지한다. 창의적 우회는 주변 표현에만 적용한다.
- 여성 친구 모드에서는 연애, 질투, 소유 표현을 추가하지 않는다. 여자친구 모드도 저장된 관계와 현재 요청에 근거한 표현만 허용한다.

## 생성 동작

- 생성 프롬프트는 요청된 강도와 그 단계의 허용 장치를 명시한다.
- 7단계의 후보 세 개는 순서대로 `상황 빗대기`, `장난스럽게 암시`, `조용한 여운` 전략을 사용한다.
- 출력 검증은 기존 중복, 허용되지 않은 장치, 사실 모순, 명시적 의도 보존 검사를 계속 수행한다.
- 기존처럼 최초 출력이 검증에 실패하면 불투명한 규칙 ID만 제공해 한 번 재시도한다.

## 저장 및 호환성

- `IndirectnessLevel` 타입과 API 입력 범위를 1~7로 확장한다.
- 답장 요청 테이블의 체크 제약을 `BETWEEN 1 AND 7`로 변경하는 마이그레이션을 추가한다.
- 기존 저장값 1~5는 의미가 바뀌지 않으며 별도 데이터 변환이 필요 없다.
- 브라우저 기본 설정은 계속 3단계이고, 이미 저장된 1~5 값도 그대로 읽는다. 새 6~7 값도 저장하고 다시 불러올 수 있다.

## 검증

- 정책 단위 테스트에서 6·7단계 장치와 1~7 범위 검증을 확인한다.
- 생성 서비스 테스트에서 7단계 세 후보 전략과 안전 예외를 확인한다.
- API 테스트에서 6·7을 허용하고 8을 거부하는지 확인한다.
- 컴포넌트 테스트에서 설정 및 요청 슬라이더가 7까지 선택·저장·전송하는지 확인한다.
- 스키마 및 마이그레이션 테스트에서 DB 체크 제약이 1~7인지 확인한다.

## 제외 범위

- 답장 후보 개수 세 개는 변경하지 않는다.
- 전체 대화 분석, 프로필 추출, 검색·검색결과 순위는 변경하지 않는다.
- 자동으로 사용자의 기존 기본 강도를 6이나 7로 올리지 않는다.
