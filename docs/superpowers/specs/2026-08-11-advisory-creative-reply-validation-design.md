# 6·7단계 권고형 답장 검증 설계

## 배경

현재 답장 생성기는 모든 검증 규칙을 동일한 실패 조건으로 취급한다. 강도 7은 비유, 암시, 역설, 여운을 요구하지만, 생성 결과에 프로필에서 확인되지 않은 `ㅋㅋ`, `~`, 이모지 등이 포함되거나 금전 관련 의도가 간접적으로 표현되면 두 번의 생성 결과를 모두 폐기하고 500을 반환한다. 실제 사용에서는 `EXPLICIT_INTENT_AMBIGUOUS`와 `UNSUPPORTED_PERSONAL_DEVICE`가 연속으로 발생했다.

## 목표

- 1~5단계의 현재 보수적 검증 동작을 유지한다.
- 6~7단계에서는 구조 오류를 제외한 콘텐츠 검증을 차단이 아닌 주의 정보로 제공한다.
- 6~7단계가 감정과 뉘앙스를 창의적으로 해석할 수 있게 한다.
- 각 답장에 전달 의도, 실제 퍼스널 컨텍스트 근거, 주의 배지를 표시한다.
- 모델이 존재하지 않는 퍼스널 근거를 만들어 UI에 노출하지 못하게 한다.
- 답장 본문만 복사되도록 기존 수정·복사 흐름을 유지한다.

## 비목표

- 1~5단계의 검증 정책을 완화하지 않는다.
- 실제 과거 메시지를 근거로 직접 인용하지 않는다.
- 모델 또는 API 장애를 숨기지 않는다.
- 콘텐츠 검증을 삭제하지 않는다. 6~7단계에서도 검증은 수행하되 결과를 경고로 전환한다.

## 정책

### 1~5단계

현재와 동일하다. 다음 규칙을 위반하면 한 번 재생성하고, 두 번째 결과도 위반하면 `ReplyGenerationValidationError`를 반환한다.

- 중복 답장
- 관계 범위 위반
- 강요·협박·비난 등 안전 및 자율성 위반
- 프로필에서 확인되지 않은 말투 장치
- 원문에 없는 구체적 사실
- 저장된 사실과의 모순
- 실제 금전 결정, 동의, 안전 조치, 단호한 거절, 중요한 약속의 불명확한 표현

### 6~7단계

모델 프롬프트에는 위 항목을 계속 피하라고 지시한다. 그러나 생성 결과가 콘텐츠 규칙을 위반해도 답장을 폐기하거나 재생성하지 않는다. 검증 결과를 답장별 주의 정보로 변환하여 세 후보를 그대로 반환한다.

감정과 뉘앙스 추론은 허용한다. 사람, 사건, 금액, 날짜, 약속 등 구체적 사실의 추측도 차단하지는 않지만, 검증기가 감지하면 반드시 주의 배지를 표시한다. 이 결정은 사용자가 6~7단계의 창의성을 우선하고 UI에서 직접 판단할 수 있게 하려는 것이다.

구조 검증만 강제한다. 응답을 정확히 세 후보와 정해진 전략 순서로 파싱할 수 없으면 한 번 재생성하고, 다시 실패하면 오류를 반환한다.

## 경고 모델

검증기는 전역 규칙 ID 집합 대신 후보별 결과를 반환한다. 각 후보의 규칙 ID는 다음 사용자용 경고으로 변환한다.

| 검증 규칙 | 사용자 경고 |
| --- | --- |
| `DUPLICATE_TEXT` | `답장 간 표현 유사` |
| `RELATIONSHIP_FORBIDDEN_CUE` | `관계 범위 주의` |
| `AGENCY_OR_SAFETY_VIOLATION` | `갈등·안전 주의` |
| `UNSUPPORTED_PERSONAL_DEVICE` | `평소 말투와 다를 수 있음` |
| `UNSUPPORTED_SPECIFIC_FACT` | `사실 추측 포함` |
| `FACT_CONTRADICTION` | `프로필과 다를 수 있음` |
| `EXPLICIT_INTENT_AMBIGUOUS` | `중요 의도 불명확` |

6~7단계의 모든 후보에는 별도로 `감정 해석 포함` 경고를 추가한다. 경고 문구는 모델이 작성하지 않고 서버의 고정 매핑으로 생성한다.

중복 검증은 정규화된 본문이 같은 모든 후보에 `답장 간 표현 유사`를 표시한다. 다른 규칙은 해당 규칙을 실제로 위반한 후보에만 표시한다.

금전 관련 보호 분류도 좁힌다. `돈`, `입금`, `송금`이라는 명사가 포함됐다는 사실만으로 중요한 금전 결정으로 분류하지 않는다. 요청, 수락, 거절, 상환, 비용 배분 등 실제 결정을 나타내는 의도일 때만 명확성 검증을 적용한다. 이 변경은 1~7단계에 공통으로 적용하되 실제 보호 결정의 검증 강도는 유지한다.

## 퍼스널 컨텍스트 근거

서버는 대상 참가자의 `participantProfiles`에서 요청별 허용 근거 목록을 만든다.

```ts
type PersonalContextEvidence = {
  id: string;
  summary: string;
};
```

- 근거는 분석된 프로필 사실에서만 생성한다.
- 각 요약은 `종류: 값 · 조건: ... · 예외: ...`의 고정 형식으로 만들고 전체를 120자로 제한한다.
- 조건이나 예외가 없으면 해당 구간을 생략한다.
- 원문 대화는 인용하지 않는다.
- 모델에는 근거 ID와 요약을 전달하고 후보당 0~2개 ID만 선택하게 한다.
- 서버는 모델이 반환한 ID를 허용 목록과 대조한다. 존재하지 않는 ID와 중복 ID는 제거한다.
- 유효한 근거가 없으면 UI에는 `현재 상황과 답장 의도만 사용`을 표시한다.

모델이 반환하는 근거 ID는 설명용 선택 정보이며, 답장 검증의 진실 공급원은 계속 서버가 로드한 컨텍스트와 사실 검증기이다.

## 응답 계약

공개 답장 후보에 근거와 경고를 추가한다.

```ts
type ReplyWarning =
  | "emotional_inference"
  | "duplicate_text"
  | "relationship_boundary"
  | "agency_or_safety"
  | "personal_style_mismatch"
  | "specific_fact_inference"
  | "profile_conflict"
  | "important_intent_ambiguity";

type ReplyCandidate = {
  strategy: ReplyStrategy;
  text: string;
  intentLabel: string;
  riskLabel: string | null;
  contextBasis: string[];
  warnings: ReplyWarning[];
};
```

모델의 구조화 응답에는 `contextBasisIds`를 추가한다. `contextBasis`와 `warnings`는 서버가 검증 후 작성하므로 모델이 최종 표시 값을 직접 통제하지 않는다.

## 생성 흐름

1. 현재 대화, 검색된 관련 맥락, 방 메모리, 참가자 프로필을 기존 방식으로 로드한다.
2. 참가자 프로필에서 허용 근거 목록을 만든다.
3. 모델에 생성 정책, 허용 근거 목록, 현재 컨텍스트를 전달한다.
4. 모델이 세 후보와 후보별 `contextBasisIds`를 반환한다.
5. 서버가 구조와 전략 순서를 검증한다.
6. 서버가 후보별 콘텐츠 검증을 실행한다.
7. 1~5단계는 현재처럼 콘텐츠 위반을 재생성 또는 오류로 처리한다.
8. 6~7단계는 콘텐츠 위반을 경고로 매핑하고 즉시 세 후보를 반환한다.
9. 근거 ID를 검증된 요약으로 변환하고, 유효한 ID가 없으면 고정된 대체 문구를 사용한다.
10. 요청과 후보, 근거 요약, 경고를 암호화해 저장한다.

## 저장소 변경

`reply_candidates`에 다음 암호화 컬럼을 추가한다.

- `encrypted_context_basis`: 암호화된 문자열 배열
- `encrypted_warnings`: 암호화된 `ReplyWarning` 배열

기존 후보 데이터와 호환되도록 두 컬럼은 nullable로 추가한다. 새로 생성하는 후보에는 항상 값을 저장한다. 암호화되지 않은 근거 또는 경고 본문은 데이터베이스에 저장하지 않는다.

## UI

각 답장 카드는 다음 순서로 렌더링한다.

1. 추천 답장 본문
2. 전달 의도
3. 퍼스널 컨텍스트 근거 최대 2개
4. 경고 배지
5. 기존 수정 및 복사 동작

6~7단계의 `감정 해석 포함` 배지 아래에는 다음 고정 안내를 표시한다.

> 감정과 뉘앙스를 창의적으로 해석한 표현이에요. 보내기 전에 실제 의도와 맞는지 확인해 주세요.

경고와 근거는 답장 본문 복사에 포함하지 않는다. 실제 과거 메시지는 UI에 표시하지 않는다.

## 오류 처리

6~7단계의 콘텐츠 경고는 500을 발생시키지 않는다. 다음 경우에만 생성 요청이 실패한다.

- OpenAI API 또는 네트워크 실패
- 두 번 모두 구조화 응답을 파싱할 수 없음
- 세 후보 또는 전략 순서가 두 번 모두 잘못됨
- 서버 또는 데이터베이스 오류

기존의 일반화된 오류 응답과 민감정보를 남기지 않는 로그 정책은 유지한다.

## 테스트

- 1~5단계에서 기존 콘텐츠 차단 회귀 테스트를 유지한다.
- 6~7단계에서 각 기존 규칙 위반이 후보별 경고로 반환되는지 검증한다.
- 6~7단계의 `EXPLICIT_INTENT_AMBIGUOUS`와 `UNSUPPORTED_PERSONAL_DEVICE`가 500을 만들지 않는지 검증한다.
- 단순 금전 관련 칭찬이 중요한 금전 결정으로 분류되지 않는지 검증한다.
- 실제 송금 요청·수락·거절은 계속 중요한 결정으로 분류되는지 검증한다.
- 허용 목록에 없는 근거 ID가 제거되는지 검증한다.
- 관련 근거가 없을 때 고정 대체 문구가 표시되는지 검증한다.
- UI가 전달 의도, 근거, 경고 배지를 표시하는지 검증한다.
- 복사 동작이 답장 본문만 복사하는지 검증한다.
- 새 암호화 컬럼 저장과 기존 nullable 행 호환성을 검증한다.

## 완료 조건

- 강도 6·7에서 콘텐츠 검증 규칙 때문에 500이 발생하지 않는다.
- 강도 1~5의 기존 검증 동작이 바뀌지 않는다.
- 모든 6·7단계 후보에 `감정 해석 포함` 안내가 보인다.
- 각 후보에 검증된 퍼스널 컨텍스트 근거 또는 고정 대체 문구가 보인다.
- 감지된 콘텐츠 위험이 후보별 배지로 보인다.
- 근거와 경고가 암호화돼 저장되고 답장 복사에는 포함되지 않는다.
