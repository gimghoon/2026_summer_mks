# 시간순 프로젝트 기록 재구성 설계

- 작성일: 2026-08-14
- 상태: 사용자 구성 승인
- 대상: `docs/project-summary`의 Markdown 문서 3개

## 목적

현재 주제별로 나뉜 세 문서를 사용자의 행동과 결정이 이어지는 시간순 기록으로 다시 작성한다. 독자는 사용자가 처음 어떤 서비스를 원했고, 어떤 선택을 했으며, 실제 사용 중 무엇을 발견해 어떻게 고쳤는지를 순서대로 이해할 수 있어야 한다.

## 구성

### 1편: 아이디어 구체화와 초기 설계

- 고정된 `여자어` 콘셉트를 선택한 과정
- 한국 20대 여성의 간접적인 감정 표현을 강조한 결정
- TXT 업로드와 붙여넣기를 모두 지원하기로 한 과정
- 방별 맥락, 참여자 프로필, 사용자 교정 방식 결정
- 친구·여자친구 모드, 강도 설정, 답장 세 개와 개인용 MVP 범위 확정

### 2편: MVP 개발과 로컬 테스트

- 저장소 생성과 로컬 개발환경 준비
- 인증, PostgreSQL, 암호화, TXT/CSV 가져오기 구현
- 분석·검색·프로필·답장·모바일 UI 구현
- 사용자가 로컬에서 직접 시험하면서 발견한 로그인, 45% 분석 정지, 503, 답장 500, Next.js 캐시·포트 문제
- 문제별 수정과 테스트 결과

### 3편: 배포와 기능 고도화

- GitHub 연결, 브랜치 병합과 기여 기록 설정
- Render와 PostgreSQL 배포, 마이그레이션과 로그인 이동 문제 해결
- 우회 강도 6·7, 창의적 검증, 추가 설명 재시도 개선
- 퍼스널 컨텍스트 근거 표시와 필수 반영 모드
- `PERSONAL_CONTEXT_NOT_REFLECTED` 검증 완화
- 현재 상태와 앞으로의 운영 주의사항

## 서술 형식

각 주요 사건은 가능한 한 다음 순서를 따른다.

1. `내가 요청한 것` 또는 `내가 한 행동`
2. `그때 확인한 문제나 결정`
3. `실제로 바뀐 내용`
4. `결과와 다음 단계`

대화의 모든 짧은 승인 응답을 나열하지 않고, 제품 방향을 바꾸거나 실제 작업을 시작하게 한 선택으로 묶어 기록한다. 날짜가 확실한 설계·커밋은 날짜를 사용하고, 정확한 날짜를 확인하기 어려운 대화는 단계 안에서 상대 순서만 보존한다.

## 개인정보와 범위

- 실제 카카오톡 원문은 싣지 않는다.
- 비밀번호, 해시, API 키와 암호화 키의 실제 값은 싣지 않는다.
- 방·참여자 UUID는 장애 설명에 필요하지 않으므로 싣지 않는다.
- 환경변수 이름과 재현 가능한 일반 명령만 기록한다.
- 기존 상세 설계의 모든 내부 구현을 반복하지 않고, 사용자의 요청과 그 결과를 중심으로 쓴다.

## 완료 조건

- `docs/project-summary`에는 Markdown 파일이 정확히 3개만 존재한다.
- 세 파일의 사건 순서가 서로 겹치지 않고 1편에서 3편으로 이어진다.
- 각 파일의 제목과 도입부만 읽어도 해당 시기를 알 수 있다.
- 주요 요청, 장애, 수정과 현재 상태가 빠지지 않는다.
- 민감한 실제 값이 포함되지 않는다.
- Markdown 공백 검사와 `git diff --check`를 통과한다.
